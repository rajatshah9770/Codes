Design patterns: General repeatable solution to a commonly occuring problem in software design

1. Creational: Used for creating or instantiating objects and classes
	a. Factory method     - Classes
	b. Abstract factory	  - Objects
	c. Builder			  - Objects
	d. Prototype		  - Objects
	e. Singleton		  - Objects
	
2. Structural: Used for structuring more than 1 classes or objects together.
	a. Adapter (Class)   - Classes
	b. Adapter (Object)  - Objects
	c. Bridge			 - Objects
	d. Composite		 - Objects
	e. Decorator		 - Objects
	f. Facade			 - Objects
	g. Flyweight		 - Objects
	h. Proxy			 - Objects

3. Behavioral: Used for identify & setting up common communication patterns among objects
	a. Interpreter      		- Classes
	b. Template method		 	- Classes
	c. Chain of responsibility	- Objects
	d. Command					- Objects
	e. Itterator				- Objects
	f. Mediator					- Objects
	g. Memento					- Objects
	h. Observer					- Objects
	g. State					- Objects
	e. Strategy					- Objects

1. Creational design patterns:
a. Factory design patter (FDP):
	It creates Obj for you, rather you initiating obj directly
	Also known as Virtual constructor
	
	How to impliment:
	- Define an interface or an abstract class for creating an obj but let the subclass decide which class to initiate.
	- runtime it creates objects based on the passed parameter while creating object
	
	Advantages:
	- Less Code changes if we change object creation process.
	- We create obj without exposing the creation logic to the client.
	- We get benefits if virtual constructor
